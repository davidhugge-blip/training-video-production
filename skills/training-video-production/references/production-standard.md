# 制度培训视频通用制作规范

## 1. 适用范围与目标

本规范用于把企业制度类 DOCX、PDF、PPT 或 PPTX 文件制作成“一制度一视频”的规则级培训材料。成片优先确保基层员工能看懂，同时适用于主管和管理层复习。

质量目标按优先级排列：

1. 制度事实准确且可追溯。
2. 基层员工能理解并记住关键规则。
3. 一项制度可独立更新和局部重制。
4. 生产流程可自动化，但内容审批和发布审批必须由人完成。

## 2. 内容边界

### 2.1 三层表达

- 制度事实层：制度原文规定了什么。所有制度性陈述必须有来源。
- 培训解释层：用短句、图示和例子帮助理解，但不得改变条件、范围、角色或强度。
- 动作 SOP 层：系统点击路径、字段填写、材料清单和具体操作步骤。默认不进入制度培训，除非用户明确要求且有正式依据。

### 2.2 规则级培训应回答

- 本制度适用于谁、什么场景。
- 谁负责、谁审核、谁审批、谁监督。
- 必须达到的时限、金额、频次、比例和标准。
- 哪些行为禁止，违反后有什么责任或后果。
- 哪些附件、方案或记录与制度有关。

### 2.3 不得自动扩写

- 制度未定义的角色、流程、数值、例外或处罚。
- 参考方案中的动态排期、预算和项目做法。
- 系统路径、供应商名单、表单字段等动作级细节。
- 为了故事性而虚构的案例结论。

## 3. 来源与版本控制

### 3.1 来源优先级

1. 已确认有效的制度正文。
2. 制度正式附件。
3. 经用户确认只用于解释的补充材料。
4. 动态项目文件或历史版本。

低优先级来源不得覆盖高优先级来源。出现冲突时停止生产并请制度负责人裁决。

### 3.2 源文件登记字段

每个文件至少记录：

- 原文件名和相对路径。
- 文件角色：`primary_policy`、`official_attachment`、`reference_only` 或 `dynamic_project_file`。
- 制度编号、版本、发布或生效日期、有效状态。
- 页数、字节数、SHA-256、登记时间。
- 是否允许进入通用课件，以及用户确认依据。

### 3.3 稳定来源定位

解析时同时保留：

- 原始页码。
- 条款标题或条款号。
- 稳定段落索引。
- 原文片段。
- 原文片段哈希。

仅保留模型总结不足以作为来源证据。

## 4. 制度事实控制件

### 4.1 制度证据台账

每条规则至少包含：

| 字段 | 要求 |
|---|---|
| `rule_id` | 唯一且稳定，例如 `TIME-001` |
| `source_pages` | 原文件页码数组 |
| `source_paragraphs` | 稳定段落索引数组 |
| `article` | 条款或章节 |
| `category` | 目的、范围、职责、时限、金额、频次、审批、禁止、责任等 |
| `source_text` | 原文数组，不自行修饰 |
| `normalized_rule` | 保持原意的规则化表达 |
| `risk_tokens` | 必须机械核验的数字、角色、否定词或责任词 |
| `training_treatment` | `include`、`mention` 或 `exclude` |

规范化表达不得把“可以”改成“必须”，不得把“原则上”改成绝对要求，不得省略前提、范围、例外和审批层级。

### 4.2 规则覆盖矩阵

覆盖矩阵建立规则到灯片的唯一主映射，并记录页面标题、讲稿位置和处理方式。

- 每条 `include` 或 `mention` 规则必须有唯一主页面。
- `exclude` 规则不进入灯片，但必须保留排除原因。
- 一页可承载多条相关规则。
- 总结页只能复盘已出现规则。
- 不允许灯片或讲稿出现无法回到规则编号的新制度性陈述。

### 4.3 高风险字段机械校验

以下字段不得只依赖人工浏览：

- 制度编号、名称、版本和生效日期。
- 金额、比例、频次、期限和提前量。
- 岗位、部门、审核人和审批人。
- “必须”“不得”“至少”“以内”“不超过”等强度词。
- 禁止项、责任后果和附件名称。

## 5. 九阶段生产流程

流程先锁定课件模式：默认`native_generation`走完整PPT设计与生成门禁；只有用户明确指定现成PPT/PPTX直接转视频时，才使用`existing_finished_ppt`。后者保留原页面比例、内容、页序和视觉，以“既有PPT直接使用确认”替代视觉方向、图片后端、单页样稿及全套PPT生成授权，不替代制度事实、讲稿、媒体和发布门禁。

| 阶段 | 必须产物 | 人工门禁 |
|---:|---|---|
| 1 源文件登记与核验 | 来源清单、哈希、版本结论 | 正式来源无歧义 |
| 2 制度事实确认 | 证据台账、事实校验结果 | 高风险字段已核对 |
| 3 分页大纲确认 | 大纲、覆盖矩阵、课件外信息 | 用户明确确认大纲 |
| 4 视觉方向确认 | 视觉编码和页面骨架 | 用户明确确认视觉 |
| 5 图片后端确认 | 后端与外发范围说明 | 用户明确确认后端 |
| 6 单页样稿确认 | 代表页样稿及 QA | 用户明确确认样稿 |
| 7 全套 PPT 和讲稿 | PPTX、逐页讲稿、来源映射 | 用户批准灯片和讲稿 |
| 8 配音字幕与视频 | 逐页音频、SRT、成片、媒体 QA | 在线 TTS 另行授权 |
| 9 最终审批与发布 | 审批记录、发布版本 | 制度负责人和发布人批准 |

在`existing_finished_ppt`模式中，阶段4视觉方向、阶段5图片后端、阶段6生成样稿及全套PPT生成授权记为“不适用”，由“既有PPT直接使用确认＋实际页面渲染检查”替代；阶段7仍审批既有整套页面与讲稿的内容对应关系，但不重新审批视觉方案或重新生成PPT。

不得把上一阶段的“可以继续”扩大解释为下一阶段需要的外发授权或发布授权。

## 6. PPT 标准

### 6.1 主路线

- 试制和批量生产优先使用图片式 PPT，主引擎为 `codex-ppt`。
- 逐页生成、逐页保存提示词、逐页记录状态，支持单页重做。
- 正式 PPTX 必须写入逐页讲稿备注并通过 OpenXML 和渲染检查。
- 若用户要求对象级可编辑，再切换可编辑 PPT 路线；不得默认牺牲视觉质量。

### 6.2 既有成品PPT路线

- 只有用户明确确认“既有成品PPT，直接转视频”时启用；PPT格式制度源材料、历史文件或视觉参考不自动触发。
- 保留原PPT页面宽高比、全部内容、页序和视觉；允许按原比例渲染为清晰的视频画面，但不得裁切、拉伸或改变页面比例。
- 制度源文件核验、证据台账、规则覆盖、逐页来源映射、讲稿审批、在线服务授权、媒体QA和发布审批保持不变。
- 合成前检查字体替换、缺字、动画、切换、嵌入视频和音频。发现动态内容时暂停，由用户批准静态化或选择保留动态效果的专用路径。
- 旧式`.ppt`先转换为可核验的`.pptx`并复核转换结果。

### 6.3 页面密度

- 每页一个核心问题。
- 标题短且直接，正文优先短句、数字卡、流程图或对照表。
- 关键数字必须同时用文字说明，不只靠颜色。
- 小字、复杂表格和长段制度原文只在确有必要时出现。
- 页数不固定，以学习效果和内容完整性为准。

### 6.4 集团母体系

以下页面骨架只适用于`native_generation`原生制作PPT；`existing_finished_ppt`保留已确认的原视觉，不强制套用16:9骨架：

- 16:9 页面骨架。
- 统一标题层级和制度编号区。
- 统一卡片圆角和风险语义色。
- 统一页面类型库：封面、目录、规则卡、时间轴、职责图、审批关系、风险警示、总结。
- 统一字幕安全区。

条线通过主色、辅助色、图形母题、线条形态和图标语言建立区别。条线色表达专业归属，语义色表达风险状态，不得混用。

### 6.5 字幕区域

`native_generation`模式使用页面内字幕安全区：

- 成片画布：1920×1080，仍保持完整 16:9，不因字幕增加左右留白。
- PPT 全页背景必须铺满 16:9。
- 底部 `y=990–1080` 预留 90px 安全区。
- 安全区内不得放正文、图表、页码、制度编号或关键装饰。
- 字幕合成时在安全区叠加深色字幕带；建议 `#111827`。
- 字幕字号固定44px、单行；常规目标宽度1500px，硬上限1600px，并以真实字体测量确认。禁止用固定字符数机械截断完整句义。

`existing_finished_ppt`模式使用页面外字幕栏：

- PPT页面完整保留；在页面画布之外向下扩展全宽字幕栏，成片不强制16:9。
- 字幕栏高度、字幕字号、描边和垂直边距按PPT页面渲染高度缩放；字幕目标宽度、硬上限和水平边距按视频宽度缩放。1920×1080页面对应90px字幕栏、44px字幕、1500/1600px宽度阈值；1440×1080的4:3页面对应90px字幕栏、44px字幕、1125/1200px宽度阈值。
- 默认使用`#111827`深色字幕栏和白色单行字幕；品牌色或条线色需另行确认。
- 编码所需偶数像素通过渲染尺寸选择或最多1px画布补齐处理，不得拉伸PPT。

## 7. 讲稿标准

- `speech.md` 使用 `## Slide N: 页面标题` 的稳定标题格式。
- 逐页讲稿和灯片一一对应，不跨页讲新规则。
- 用基层员工熟悉的语言解释术语，但不得改变制度用词的强度。
- 金额、时间、频次、角色和禁止项必须与证据台账完全一致。
- 可以添加非制度性的理解提示，但要明确其解释属性，不得制造新要求。
- 讲稿批准后作为字幕和配音的唯一文本来源。

## 8. 配音、字幕与视频标准

### 8.1 配音

- 正式默认使用已通过基准五页技术QA及人工复听的MeloTTS＋MFA本地链路。
- MeloTTS使用官方中文固定音色`ZH`、CPU运行、速度0.95；模型仅从本地缓存加载，不启用真人声音克隆或在线回退。
- 本地生成前必须完成官方音色试听与确认记录；英文字母、制度编号和阿拉伯数字须经术语门禁并先批准自然中文讲稿改写，生僻词须人工复听。
- 项目清单必须记录本地官方音色、速度、确认依据、禁用声音克隆及禁用在线回退；项目级媒体门禁按明确输出标签核对WAV、媒体清单和完整QA报告。
- MeloTTS最终WAV必须经MFA普通话强制对齐生成同源字幕时间轴；禁止字符比例估算。
- Edge WordBoundary链路仅作为显式在线备选；使用前必须针对当前材料取得明确外发授权，不得由本地链路自动回退。
- 本次默认升级不等于允许自动改写讲稿或覆盖既有正式媒体。
- 保留服务商、声音、语速、生成时间、文本范围和授权记录。
- 逐页生成音频，以便局部重制。

### 8.2 字幕

- 字幕文本必须与批准讲稿逐字一致。
- 每页保存独立 SRT，并合并一份全程 SRT。
- `native_generation`模式默认44px、白字、细黑描边、单行、底部居中，使用页面内90px字幕带；`existing_finished_ppt`模式按页面高度同比例缩放并使用页面外字幕栏。两种模式均不得遮挡灯片内容或动态缩小字号。
- 1920×1080页面基准下，常规目标宽度1500px，受保护内容硬上限1600px；其他尺寸同比例缩放。
- 字幕显示单元优先保持完整句子；超宽时依次在分号或冒号、逗号、自然语义连接词和词语边界处分段。
- 能完整容纳的书名号、引号和括号内容必须成对显示；超长内容跨字幕时，开放标点跟随首段文字、闭合标点跟随末段文字，禁止标点单独显示；“先、再、但、并”等连接词不得悬在字幕末尾。
- 制度名称、制度编号、金额、日期、百分比、计量单位和岗位名称不得从内部拆开。
- 单条优先显示1.2—6秒；不足1秒的短片段在条件允许时合并，超过约7秒时继续按语义拆分。
- 逐页SRT、全程SRT、ASS和成片使用同一套字幕显示单元。仅返修字幕时复用已批准音频及时间轴，不重新调用TTS。

### 8.3 视频

- FFmpeg 为核心合成工具，避免长期依赖 PowerPoint 桌面端批量导出。
- `native_generation`输出1920×1080；`existing_finished_ppt`按“原PPT渲染画面＋外置字幕栏”动态确定分辨率，不强制16:9。两种模式均为30fps、H.264、AAC、`yuv420p`、`faststart`。
- 音频目标响度约 -16 LUFS，真峰值不高于 -1.5 dBFS。
- 每页尾部可增加约 0.55 秒呼吸时间。
- 必须校验完整解码、页序、时长、音画对应和异常静音。
- 字幕时间必须来自生成该页音频的同一词级时间流；旧项目仅返修字幕且未保存词级事件时，可以合并既有SRT时间段，但禁止按字符比例重新估算。
- 媒体后端必须在执行前锁定，失败时停止并断点续跑，不得静默切换配音或视频工具。

## 9. 可重制目录与状态

推荐每项制度使用独立目录：

```text
POLICY_ID/
├── sources/
├── extraction/
├── evidence_ledger.json
├── outline_rule_map.json
├── 规则覆盖矩阵.md
├── outline.md
├── deck_spec.json
├── speech.md
├── prompts/
├── origin_image/
├── audio/
├── subtitles/
├── video/
├── qa/
├── approvals/
└── manifest.json
```

`manifest.json` 记录各阶段状态和当前门禁；未经最终批准，状态不得写成“已发布”。

## 10. 验收标准

### 10.1 内容

- 所有制度性陈述可追溯到规则编号和原文。
- 纳入培训的规则全部有唯一主页面。
- 编号、版本、金额、时限、频次、角色、禁止项和责任后果无偏差。
- 没有把参考文件或动作 SOP 混入制度要求。

### 10.2 视觉与学习

- 基层员工能快速识别“谁、何时、做什么、不能做什么”。
- 页面无小字堆叠、无内容溢出、无不必要装饰。
- 五条线视觉编码统一且可区分。
- 原生制作PPT的正文完全避开页面内字幕安全区；既有成品PPT的外置字幕栏不得覆盖原页面。

### 10.3 媒体

- 逐页音频、字幕、画面数量相等且顺序一致。
- 字幕与讲稿逐字一致，字号和安全区符合规范；无孤立标点、受保护内容拆分或超过当前模式计算硬上限的字幕（原生1920px宽画布为1600px，既有成品PPT按视频宽度同比例缩放）。
- 视频完整解码，实际分辨率与媒体清单一致，帧率、编码和响度合格；既有成品PPT的页面比例与字幕栏边界正确。
- 无超过 2 秒的异常静音。

### 10.4 业务发布

- 制度负责人完成内容审批。
- 基层员工代表完成理解度试看。
- 发布责任人明确批准版本。

技术 QA 通过不等于业务批准发布。

## 11. 禁止事项

- 未做证据台账就直接生成 PPT。
- 未确认大纲、视觉、后端或样稿就越级全套生成。
- 用大模型常识或外部资料补写制度规则。
- 把“可能、可以、原则上”改成绝对要求。
- 未授权将完整内部制度或讲稿发送给在线服务。
- 字幕遮挡正文；原生制作PPT为字幕改变画布比例，或既有成品PPT被强制拉伸、裁切、缩小或补成16:9。
- 未经“既有PPT直接使用确认”就跳过视觉与PPT生成门禁，或静默丢弃动画、切换、嵌入视频和音频。
- 将多项制度塞进同一视频。
- 自动标记制度负责人审批或正式发布。
